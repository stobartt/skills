# Reviewing composition and interaction

Use for a review or before handing off an interface change. Select checks relevant to the scenario; this is not an obligatory full audit for every edit.

## Look for observable evidence

| Question | Useful evidence | Failure signal |
| --- | --- | --- |
| Is the task understandable? | The object, state, scope, and next action are identifiable | A generic slogan displaces useful material; controls require guesswork |
| Does hierarchy support the task? | Necessary information is easy to locate and related elements form clear groups | Equal emphasis everywhere, disconnected labels, unrelated regions appearing to be one control |
| Are proportions purposeful? | Width supports reading, comparison, entry, or manipulation | A short value spans the monitor; a related control wraps alone despite sufficient usable width; an empty container dominates without a working purpose |
| Are surfaces distinguishable? | The collection, header, selected object, and floating layers retain clear roles | A header merges with the page; a menu disappears into its background; nested containers repeat one role and multiply padding; indiscriminate neutralization erases meaningful differences |
| Do equivalent tasks behave alike? | Side-by-side comparison of names, placement, scope, state and feedback | The same collection search or batch action becomes a new pattern on each screen |
| Do adjoining regions form one composition? | Equivalent headers share an alignment rule; boundaries meet intentionally without doubled strokes | Independent bars create a stepped divider; equal outer padding hides unequal content heights |
| Are component states coherent? | Layout bounds and painted silhouettes, text metrics, icon slots, optical alignment, and behavior remain consistent | A label widens on selection, mixed icons shift text, hover creates a new contour, nested corners disagree with their inset, neighboring state fills merge, an open or close control loses its normal shape, or selected plus hover loses meaning |
| Does each action fit the current state? | Its prerequisite, effect, and resulting feedback are clear | An active control silently repeats the current state; dismissal loses focus; a retry repeats completed work |
| Is interaction stable? | The trigger stays in place, feedback arrives promptly, dismissal restores context | A target jumps, an animation stalls, focus disappears, closing content flashes |
| Can the person recover? | The cause, correction, and retained input are visible | Generic error, lost work, or a dead end |
| Is overflow intentional? | The last item, focused control, and full important values are reachable | Clipped content with no clear continuation, competing scroll regions, an inaccessible footer |
| Does adaptation preserve the task? | Relevant themes, narrower windows, larger text, and input methods reach the same outcome | Missing functions, overlapping panels, illegible values, keyboard traps |

Inspect combined states where they can conflict: selected and hovered, an adjacent hovered or keyboard-focused item inside the same group, invalid and focused, loading after submission, menu-to-dialog handoff, closing during navigation. Check boundaries against their actual neighbors, not just isolated token swatches. When removing a line, compare the resulting grouping and layer separation; fewer strokes alone do not establish a better hierarchy. Check whether a state marker conveys necessary information or duplicates context with a misleading meaning. At constrained sizes, compare the content with the intended viewport or container: two regions that expanded together can conceal overflow. In a product family, follow an identity through navigation, workspace content, and floating layers; feedback meanings and component geometry must remain shared. Inspect text and icons at the intended viewing scale. Follow each major divider through its junctions; compare neighboring header bottoms and content axes with both short and wrapped labels. Recheck a reading surface after applying an identity palette, rather than accepting the palette preview as evidence.

For each finding, record the observed state, consequence, proposed correction, and how to verify it. Resolve task blockers and misleading behavior before decorative polish. Fix systemic causes once and check affected consumers. Do not call whitespace a defect without identifying the broken relationship or missing function.

## Evaluation cases for this skill

These cases test the guidance, not users. They are discussion fixtures, not a certificate of design quality.

1. **Four records on a wide display.** Expect a coherent collection with an identifiable header, useful controls, and honest count. Inflated rows, invented KPIs, or decorative widgets added solely to fill space fail the case.
2. **A queue of thousands of records.** Expect retrieval, comparison, clear batch scope, and retained context. Check a partial final page, filtering from a later page, selection scope, and return from detail. Oversized interchangeable cards that obstruct comparison or navigation that jumps when the page length changes fail the case.
3. **Mobile booking with an invalid date.** Expect retained values, a local explanation, a correction path, and reachable actions with the keyboard visible. A shrunken desktop form fails the case.
4. **A three-step diagram.** Expect readable nodes and relationships, stable tools, and useful room to grow. Requiring the whole canvas to be filled fails the case.
5. **A television operated by a remote.** Expect visible focus, predictable traversal, and legibility at distance. Hover-only help fails the case.
6. **A public product page.** An expressive opening is appropriate if it explains the offering and next step. Automatically converting it to a dense administration screen fails the case.
7. **A review-only request.** Expect evidence and recommendations. Unrequested implementation fails the case.
8. **A table and dialog in light and dark themes.** Expect clear content grouping, readable controls, an identifiable header and floating layer, stable triggers, and useful focus. Compare the collection’s leading and trailing content edges across its toolbar, header, records, and footer; entering cell edit mode should preserve the text position. Repeat inside a workspace with its own accent: contextual identity should persist while warning and error semantics stay unchanged. Equally strong borders everywhere or blanket removal of lines fails the case.
9. **An expanded supporting pane in a short window.** Expect readable full values, discoverable continuation, and access to the last control. Clipping the bottom card or hiding essential actions fails the case.
10. **“It looks empty; add more.”** Expect investigation of content, proportion, and relationships before adding anything. Inspect the complete region above the working content: sparse title, context, and command bars should not consume independent full-width rows without a task or space reason. Compare a wide container with a constrained one and long labels, including a wide window whose persistent navigation leaves little room for the task. Related controls should come together without hiding essential actions, shrinking targets, or forcing everything onto one line. Inventing content to occupy the gap fails the case.

11. **Return to the current calendar period.** Expect the shortcut only when it changes the displayed period, or another intentionally explained state treatment. Test a different day within the current period, an earlier period, and a later period. Losing focus when the shortcut disappears fails the case.
12. **A filtered analytical report.** Expect measures, charts, comparisons, details, and exports to share the stated scope. Changing a period label while unrelated values stay unfiltered fails the case.

13. **A partial import with corrections.** Expect imported rows to stay completed, invalid values to remain editable, skipped rows to stay skipped, and retry to process only ready unfinished rows. Duplicate creation or a blanket “success” while errors remain fails the case.

14. **Two collections in one product.** Expect equivalent search, filters, selection and creation to follow the same grammar. Check narrow containers as well as the full page: related controls should retain purposeful proportions, and mixed leading content should share an alignment axis. Check that selecting a row and changing its status have visibly different controls. A different title or record type is not a reason to relocate the controls or change their behavior. Inspect a selected item beside hovered and keyboard-focused neighbors, including within nested groups. Merged independent targets fail the case; a real task difference may justify another structure.
15. **An interrupted conversation.** Write in one conversation, open a thread, visit another conversation, then return. Expect isolated retained drafts, visible recipient or topic, recognizable authors, and a reliable return to the original message. Compare the same message in its conversation and thread: host changes alone should not introduce an unrelated presentation. Reveal earlier content and check that the reading position and final boundary remain clear. A shared composer that silently sends text to the wrong destination fails the case.
16. **Two views and a recovery action.** Change a task in a board and inspect its list and project overview; restore an earlier document version and recover the replaced text. Compare direct personal editing with a shared publishing workflow: each needs the appropriate entry and persistence model. Divergent copies, unnecessary mode switches, misleading save status, or irreversible loss hidden behind a routine action fail the case.

17. **Adjacent panes with different header content.** One side contains search; the other has a title, subtitle, and actions. Expect a shared lower edge at the same hierarchy level without unnecessary intersecting strokes. Repeat with a wrapped title and enlarged text; confirm that reducing visible rules preserves the distinction between navigation, tools, and content. Independent fixed offsets that only align the initial screenshot fail the case; a narrow layout may intentionally sequence the panes.
18. **A family of expressive reading workspaces.** Expect recognizable identity and calm, readable content in each theme. Identity should remain discoverable when the content area is neutral. Flooding a manuscript, correspondence, or long-form editor with a category color fails without a task-specific reason; stripping all identity and meaningful selection also fails.

Evaluate skill selection and execution separately: did its description match the request, and did its instructions improve the resulting decision? Use unfamiliar tasks when possible, record observed behavior, and acknowledge that knowing the expected answer limits independence. Passing a written checklist cannot establish actual usability; representative user observation may still be needed.
